 Week 3: Software Requirements Specification

1. Introduction

CampusFix is a system for reporting and managing university facilities maintenance problems.

The purpose of this SRS is to define the requirements that will guide the design and development of the CampusFix prototype.

 2. Functional Requirements

The system shall:

1. Allow students and staff to report facilities problems.
2. Record maintenance requests.
3. Allow authorized users to view requests.
4. Allow requests to be prioritized.
5. Allow requests to be assigned to maintenance staff.
6. Allow maintenance staff to update request status.
7. Allow users to track request progress.
8. Allow maintenance staff to indicate when a problem is resolved.
9. Allow completed requests to be closed.
10. Maintain records of maintenance requests.

 3. Non-Functional Requirements

 Usability

The system should be simple and easy to use.

Security

Only authorized users should access appropriate system functions.

 Performance

The system should respond to normal user actions within a reasonable time.

 Reliability

The system should reliably store maintenance requests and their status.

 Maintainability

The system should be easy to maintain and modify.

 Data Integrity

The system should maintain accurate and consistent maintenance information.

 4. Main System Process

Report Problem → Record Request → Prioritize → Assign → Handle → Update Status → Resolve → Close

 5. Waterfall Model Relationship

These requirements will form the basis for the next stage of the Waterfall Model, which is system design. The requirements will therefore be documented before moving to the design and implementation stages.

6. Conclusion

This SRS defines the main requirements for the CampusFix prototype and provides the foundation for the next stages of the Waterfall development process
