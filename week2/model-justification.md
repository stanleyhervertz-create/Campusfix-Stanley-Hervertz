 Week 2: Waterfall Model Justification and Project Plan

Selected Process Model

The selected process model for CampusFix is the Waterfall Model.

 Why Waterfall?

The Waterfall Model is suitable for CampusFix because the project can be developed through clear and sequential stages. The requirements can be identified and documented before moving to design, implementation and testing. It also provides clear documentation and deliverables at each stage, making it suitable for managing the CampusFix prototype in an organized manner.

 Waterfall Stages

1. Requirements Analysis – identify users and system requirements.
2. System Design – design the system architecture and UML models.
3. Implementation – develop the CampusFix prototype.
4. Testing – test the system and identify errors.
5. Deployment – prepare the prototype for demonstration.
6. Maintenance – correct problems and make necessary improvements.

 Project Plan

| Week | Activity |
|---|---|

 Conclusion

The Waterfall Model will provide a structured approach to developing CampusFix, with each stage completed and documented before proceeding to the next stage.
